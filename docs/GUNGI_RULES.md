# 軍儀 (Gungi) ルール仕様書 — エンジン実装準拠版

本書は `packages/gungi-engine` が **1:1 で実装する唯一の正式仕様** である。
エンジンのテスト (`packages/gungi-engine/src/*.spec.ts`) は本書のセクション番号（例: `§5.3`）を
`describe` 名に含めて対応付けている。ルールを変更する場合は **本書 → テスト → 実装** の順に更新すること。

- ベース: 2023 年発売の公式製品版『HUNTER×HUNTER 軍儀』の **上級編**（自由配置・特殊駒あり・最大 3 段・帥ツケ可）
- 公式ルールブックの全文は入手できていないため、公開されている解説・コミュニティ実装（§14 参考資料）を突き合わせて確定させた。
- 資料間で食い違う／曖昧な箇所は 1 つに決め、**⚠要チーム確認** を付けた。一覧は §13。

## §1 用語

| 用語 | 意味 |
|---|---|
| 先手 / 後手 | 先手 = **黒 (`black`)**、後手 = **白 (`white`)** |
| 段 (tier) | スタック内での高さ。最下段が 1 段目。最大 3 段 |
| スタック | 1 マスに積まれた駒の列（下→上）。高さ = 駒数 |
| 最上段の駒 (top) | スタックの一番上の駒。そのマスの「持ち主」はこの駒の所有者とみなす |
| 持ち駒 (hand) | まだ盤上に出していない自分の駒。取られた駒は持ち駒にならない（§6.4） |
| ツケ | 駒を他の駒（敵味方問わず）の上に重ねること |
| 新 (あらた) | 持ち駒を盤上に打つこと（将棋の「打つ」に相当） |
| 寝返り | 謀のツケ／新に伴い、スタック内の敵駒を自分の駒に替えること（§7） |

## §2 盤と座標

### §2.1 盤

- 9×9 = 81 マス。
- 座標は 0 始まり: `file`（筋, 0..8, 黒から見て左→右）, `rank`（段列, 0..8）。
- **rank 0 が黒の最奥列、rank 8 が白の最奥列**。

### §2.2 前方向

- 黒の前方 = `rank` が増える方向 (+1)。
- 白の前方 = `rank` が減る方向 (-1)。
- 駒の動きの定義（§5）は「自分から見た相対座標 (横 df, 前 dr)」で書く。白の場合は盤上で 180° 回転（df・dr とも符号反転）して適用する。

### §2.3 自陣

- 黒の自陣 = rank 0, 1, 2
- 白の自陣 = rank 6, 7, 8

## §4 段とスタック

### §4.1 最大段数

- 1 マスのスタックは最大 **3 段**。4 段目を作る着手（移動・ツケ・新・配置）はすべて不可。

### §4.2 動かせる駒

- 動かせるのは **各スタックの最上段の駒のみ**。下にある駒は（自分の駒でも）動かせない。
- 最上段の駒が動くと、その下の駒が新たな最上段となる。

### §4.3 駒の段

- 駒の「段」= その駒がスタック内で何番目にあるか（1..3）。
- 駒の動ける範囲は、**移動開始時点のその駒の段** によって決まる（§5.2）。

### §4.4 帥に関する制限

- **帥の上には、いかなる駒もツケられない**（移動・新・配置のいずれでも）。したがって帥は常に最上段にある。
- 帥自身は他の駒の上にツケてよい（上級編の「帥ツケ」）。

## §5 駒の動き

### §5.1 動きの種類

| 種類 | 定義 |
|---|---|
| 歩 (step, 範囲 n) | 指定方向へ 1..n マス進める。途中のマスに駒（敵味方・高さ問わず）があればそれより先へは進めない。駒があるマス自体へは §6 の条件で着手可 |
| 走 (slide) | 指定方向へ盤端まで何マスでも進める。途中の駒による遮断は「歩」と同じ |
| 跳 (jump) | 指定オフセットのマスへ **途中の駒を飛び越えて** 直接着地する。途中にある駒の有無・高さは問わない |

### §5.2 段による拡張

移動開始時の駒の段を `t`（1..3）とする。

- 歩: 範囲 `n` は `n + (t - 1)` になる（2 段目で +1、3 段目で +2）。
- 走: 段の影響を受けない。
- 跳: オフセット `(df, dr)` に対し、着地点は `(df, dr + k)`（`k = 0..t-1`、つまり前方へ延長）。

### §5.3 各駒の動き（自分から見た相対座標）

表記: F=前, B=後, L=左, R=右, FL/FR=斜め前, BL/BR=斜め後。数字は 1 段目での範囲。

| §番号 | 駒 | 動き（1 段目） |
|---|---|---|
| §5.3.1 | 帥 | 8 方向 歩1 |
| §5.3.2 | 大 | F/B/L/R 走、FL/FR/BL/BR 歩1（将棋の竜王型） |
| §5.3.3 | 中 | FL/FR/BL/BR 走、F/B/L/R 歩1（将棋の竜馬型） |
| §5.3.4 | 小 | F, FL, FR, L, R, B 歩1（金将型） |
| §5.3.5 | 侍 | F, FL, FR, B 歩1 |
| §5.3.6 | 槍 | F 歩2、FL, FR 歩1、B 歩1 |
| §5.3.7 | 馬 | F 歩2、B 歩2、L, R 歩1 |
| §5.3.8 | 忍 | FL, FR, BL, BR 歩2 |
| §5.3.9 | 砦 | F, L, R 歩1、BL, BR 歩1 |
| §5.3.10 | 兵 | F, B 歩1 |
| §5.3.11 | 砲 | 跳 (0, +3)、L, R 歩1、B 歩1 |
| §5.3.12 | 弓 | 跳 (0, +2), (-1, +2), (+1, +2)、B 歩1 |
| §5.3.13 | 筒 | 跳 (0, +2)、BL, BR 歩1 |
| §5.3.14 | 謀 | FL, FR 歩1、B 歩1 |

例（§5.2 の適用）:

- 2 段目の兵: F, B 歩2。3 段目の兵: F, B 歩3。
- 3 段目の帥: 8 方向 歩3。
- 2 段目の砲: (0,+3), (0,+4) へ跳。
- 2 段目の弓: (0,+2),(0,+3),(±1,+2),(±1,+3) へ跳。
- 大の走は段に関係なく盤端まで。斜めの歩1 は 2 段目で歩2、3 段目で歩3。

⚠要チーム確認 (R-1): 特殊駒（砲・弓・筒）の跳の着地点と段による延長方向、および「途中の駒の高さを問わず飛び越せる」点は、公式図を直接確認できていない。

## §6 盤上の着手（移動・取り・ツケ）

### §6.1 着手の種類

手番側は自分の最上段の駒を 1 つ選び、§5 で到達可能なマス（移動先）に対して次のいずれかを行う。

| 種類 | Move `type` | 移動先の条件 |
|---|---|---|
| 移動 | `move` | 移動先が空 |
| 取り | `capture` | 移動先の最上段が **敵の駒**、かつ §6.2 の高さ条件 |
| ツケ | `stack` | 移動先にスタックがある（最上段は敵味方どちらでもよい）、かつ §6.2 の高さ条件、かつ §6.3 |

最上段が敵の駒であるマスに対しては、「取り」と「ツケ」の両方が選択肢になり得る。どちらを行うかは Move で明示する。

### §6.2 高さ条件（同段以下）

- 移動する駒の段を `t`、移動先スタックの高さを `h` とすると、**`h ≤ t` のときだけ** 取り・ツケができる。
- 例: 1 段目の駒は高さ 2 以上のスタックを取ることもツケることもできない。

### §6.3 ツケの追加条件

- 移動先の高さ `h < 3`（§4.1）。ツケた駒の段は `h + 1` になる。
- 移動先の最上段が帥であってはならない（§4.4）。

### §6.4 取りの処理

- 移動先スタック内の **敵の駒はすべて** 取られる（最上段だけではない）。
- 同スタック内の **自分の駒は残り**、元の順序のまま下に詰める。動いた駒はその上に乗る。
- 取られた駒はゲームから除外される（持ち駒にはならない）。取った側の `captured` 記録に残す。

例: 下から [白兵, 黒侍, 白槍] のスタックを黒（2 段目以上）が取ると、[黒侍, 黒(移動した駒)] になる。

## §7 寝返り（謀）

### §7.1 発生条件

- 謀が **ツケ（§6.1 の `stack`）または新（§8）で** スタックの最上段に乗ったとき、そのスタック内の敵の駒を寝返らせることができる（任意）。
- 謀の通常移動 (`move`) や取り (`capture`) では発生しない。

### §7.2 処理

- 寝返らせる敵駒は、スタック内の敵駒から任意の部分集合を選ぶ（0 個でもよい = 寝返りなし）。
- 寝返らせる駒 1 枚ごとに、**同じ種類の駒を自分の持ち駒から 1 枚消費** する。持ち駒が足りない種類は寝返らせられない。
- 寝返った駒はその位置のまま所有者が自分に変わる。元の敵駒はゲームから除外され、`captured` に記録する。
- 帥は持ち駒に存在し得ないため寝返らない。

### §7.3 指定方法

- Move の `betray` に、寝返らせる駒のスタック内インデックス（0 始まり、下から）を列挙する。省略または空配列は寝返りなし。

## §8 新（持ち駒を打つ）

### §8.1 基本

- 対局フェーズで、手番側は着手の代わりに持ち駒を 1 枚盤上に打てる（Move `type: "drop"`）。1 手として数える。

### §8.2 打てる段列（最前線ルール）

- 自分の最奥列から、**最上段が自分の駒であるマスのうち最も前方にある列** までの範囲にのみ打てる。
- 例: 黒の最上段の駒が rank 0..4 に存在し、最も前方が rank 4 なら、rank 0..4 に打てる。

⚠要チーム確認 (R-2): 「最前線」の判定に、下段に埋もれた自駒を含めるか。本仕様では **最上段の自駒のみ** で判定する。

### §8.3 打てるマス

- 空マス、または
- 最上段が **自分の駒** で高さ `< 3`、かつ最上段が帥でないスタック（ツケる形で打つ）。
- **謀のみ** 最上段が **敵の駒** のスタック（高さ `< 3`、最上段が帥でない）にも打てる。
- 新では取りは発生しない。§6.2 の高さ条件は新には適用しない。

### §8.4 寝返り

- 謀を新でスタックに乗せた場合、§7 の寝返りができる。

### §8.5 その他

- 二歩・打ち歩詰め等の将棋の制限はない。

## §9 初期配置フェーズ（自由配置）

### §9.1 開始状態

- 盤は空。両者とも 25 枚すべてが持ち駒。手番は黒。

### §9.2 配置手 (`place`)

- 手番側は持ち駒を 1 枚、**自陣（§2.3）** のマスに置く。
- 置けるマス: 空マス、または最上段が自分の駒で高さ `< 3`、最上段が帥でないスタック（自陣内でのツケ）。
- **各プレイヤーの最初の配置は帥でなければならない。**

### §9.3 配置完了 (`finishPlacement`)

- 手番側は配置の代わりに「済」を宣言できる。帥を置いていなければ宣言できない。
- **先手（黒）が済** → 黒の配置は終了。以後、白が単独で配置を続ける。
- **後手（白）が済** → その時点で **両者の配置フェーズを強制終了** する（黒が未完了でも）。
- 持ち駒が 0 になったプレイヤーは自動的に済とみなす。
- 配置しなかった駒は持ち駒として残り、対局中に新で使える。

### §9.4 手番の進行

- 両者とも未完了の間は交互に配置する。
- 一方が完了済みなら、もう一方が連続して配置する。
- 両者完了で対局フェーズに移行し、**先手（黒）から** 指す。

⚠要チーム確認 (R-3): 先手を黒とすること、配置フェーズの終了条件（後手の済で強制終了）。

## §10 禁じ手

### §10.1 自殺手（帥を取られる状態にする手）

- 着手後、**相手の次の 1 手で自分の帥が取られ得る状態になる手は指せない**（王手放置・自ら帥を取られる位置に動く手を含む）。
- 「帥が取られ得る」= 相手のいずれかの最上段の駒が §5・§6.2 に従って帥のマスへ `capture` できる。
- 例外: 相手の帥を取る手（§11.1）は、その結果自分の帥が取られ得る形であっても指せる（その時点で終局するため）。

⚠要チーム確認 (R-4): 公式ルールは「反則 = 即負け」の対面ルールと思われる。アプリでは反則手を **受け付けない（エラーを返す）** 方式とする。

### §10.2 不正な着手

§4〜§9 の条件を満たさない着手はすべて拒否され、エラーコード（§12.3）が返る。状態は変化しない。

## §11 終局

### §11.1 帥取り

- 相手の帥を取った側の勝ち（`reason: "marshalCaptured"`）。
- §10.1 により通常は発生しないが、初期配置の結果、開始直後に帥が取れる場合などに起こり得る。

### §11.2 詰み

- 手番側に合法手が 1 つもなく、かつ帥が取られ得る状態（王手）なら、手番側の負け（`reason: "checkmate"`）。

### §11.3 手詰まり

- 手番側に合法手が 1 つもなく、王手でもない場合も、手番側の負け（`reason: "stalemate"`）。

⚠要チーム確認 (R-5): 手詰まりを引き分けとする実装例もある。本仕様は将棋に倣い負けとする。

### §11.4 千日手

- 対局フェーズで **同一局面（盤面・両者の持ち駒・手番がすべて一致）が 4 回目に現れた時点で引き分け**（`reason: "repetition"`）。
- 対局開始時の局面を 1 回目として数える。
- 同じ着手で詰み・手詰まり（§11.2 / §11.3）も成立する場合は、そちらを優先する。

⚠要チーム確認 (R-6): 公式は「引き分けまたは指し直し」とされる。アプリでは引き分けで確定する。

### §11.5 投了

- 配置フェーズ・対局フェーズのいずれでも、どちらのプレイヤーも手番に関係なく投了できる（Move `type: "resign"`）。投了した側の負け（`reason: "resignation"`）。

### §11.6 時間切れ・切断

- 持ち時間や切断の判定はサーバー側の責務。サーバーは Move `type: "timeout"`（負けた側を指定）をエンジンに適用して終局させる（`reason: "timeout"`）。手番に関係なく適用可。

### §11.7 合意による引き分け

- 双方の合意確認はサーバー側の責務。合意成立時、サーバーは Move `type: "agreeDraw"` を適用する（`reason: "agreement"`）。

### §11.8 終局後

- 終局後の状態 (`phase: "finished"`) に対する着手はすべて拒否する。

## §12 エンジン API / データ形式

### §12.1 状態 (`GameState`)

- 純粋な JSON データ（クラス・Map・Set を含まない）。WebSocket 送信・JSONB 保存にそのまま使える。
- 主なフィールド: `phase`（`placement` / `play` / `finished`）, `board`（`board[rank][file]` = 下→上の駒配列）,
  `hands`, `turn`, `placementDone`, `captured`, `ply`, `positionCounts`, `result`。
- すべての関数は入力状態を変更しない（イミュータブル）。

### §12.2 着手 (`Move`)

| `type` | フェーズ | フィールド |
|---|---|---|
| `place` | placement | `player`, `kind`, `to` |
| `finishPlacement` | placement | `player` |
| `move` / `capture` / `stack` | play | `player`, `from`, `to`, `betray?`（`stack` のみ） |
| `drop` | play | `player`, `kind`, `to`, `betray?` |
| `resign` | placement / play | `player` |
| `timeout` | placement / play | `player`（負けた側） |
| `agreeDraw` | placement / play | なし |

### §12.3 エラーコード (`MoveError`)

| コード | 意味 |
|---|---|
| `GAME_FINISHED` | 終局後の着手 |
| `WRONG_PHASE` | フェーズに合わない着手種別 |
| `NOT_YOUR_TURN` | 手番でないプレイヤーの着手 |
| `INVALID_SQUARE` | 盤外・不正な座標 |
| `NOT_IN_HAND` | 持ち駒にない駒の配置・新 |
| `MARSHAL_FIRST` | 最初の配置が帥でない／帥未配置での済宣言 |
| `OUTSIDE_TERRITORY` | 自陣外への配置 |
| `OUTSIDE_DROP_ZONE` | §8.2 の範囲外への新 |
| `OCCUPIED_BY_ENEMY` | 敵駒の上への配置・新（謀の新を除く） |
| `STACK_FULL` | 3 段を超える |
| `CANNOT_STACK_ON_MARSHAL` | 帥の上へのツケ |
| `NO_PIECE` | 移動元に駒がない |
| `NOT_YOUR_PIECE` | 移動元の最上段が自分の駒でない |
| `UNREACHABLE` | §5 で到達できないマス |
| `TARGET_TOO_HIGH` | §6.2 の高さ条件違反 |
| `TARGET_NOT_EMPTY` | `move` の移動先が空でない |
| `TARGET_EMPTY` | `capture` / `stack` の移動先が空 |
| `CANNOT_CAPTURE_OWN` | 自分の駒への `capture` |
| `INVALID_BETRAYAL` | §7 の条件を満たさない寝返り指定 |
| `SELF_CHECK` | §10.1 の自殺手 |
| `INVALID_MOVE` | 形式不正 |
