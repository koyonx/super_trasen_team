# やることリスト (TASKS)

[PROJECT_OVERVIEW.md](./PROJECT_OVERVIEW.md) の準必須43pt構成に基づくタスクリスト。
フェーズ順に並んでいるが、フェーズ内のタスクは並行作業可能。
各フェーズ末の **DoD (Definition of Done)** を満たすまで次フェーズのモジュールを主戦場にしない
（「動かないモジュール = 0pt」対策として、常にデモ可能な状態を維持する）。

凡例: `[必須]` = subject の必須要件（落とすと rejected） / `(Npt)` = モジュールポイント

## Phase 0: プロジェクト基盤（意思決定と土台）

### 意思決定・ドキュメント
- [ ] 役割分担の決定（PO / PM / Tech Lead / Developers）→ [ROLES.md](./ROLES.md)
- [ ] 実装言語・フレームワークの決定（構成A: TS統一 / 構成B: FE・BE別言語）　-> TS統一構成
- [ ] AI対戦の実装方式の決定（自前探索 / 学習あり / LLM・MCP経由）
- [ ] 多言語対応の対象3言語の決定
- [ ] ブランチ戦略・PRレビュールールの策定 `[必須: 全員のコミット履歴]`
- [ ] 軍儀ルール仕様書の作成（駒の動き・ツケ・新・初期配置・勝敗・禁じ手） -> gungi.ioを参照

### リポジトリ・環境
- [ ] モノレポ scaffold（`client/` `server/` `packages/` `contracts/` `infra/`）
- [ ] `.env` + `.env.example` の整備 `[必須]`
- [ ] Docker Compose 一式（nginx TLS終端 / client / server / postgres）`[必須: 1コマンド起動]`
- [ ] HTTPS 化（自己署名 or mkcert）`[必須]`
- [ ] CI 構築（lint / typecheck / unit test / docker build / コンソールエラー検出のスモーク）
- [ ] GraphQL スキーマの初期設計とコード生成パイプライン
- [ ] DB スキーマ初期設計（マイグレーションツール導入）`[必須: 明確なスキーマとリレーション]`

### 必須ページ・認証の骨子
- [ ] Privacy Policy ページ（中身のある内容）`[必須]`
- [ ] Terms of Service ページ（中身のある内容）`[必須]`
- [ ] email + password 認証（argon2/bcrypt ハッシュ+ソルト、JWT httpOnly cookie）`[必須]`
- [ ] FE/BE 両側バリデーション基盤（スキーマ単一ソース化）`[必須]`
- [ ] README.md 骨子作成（冒頭の curriculum 行、必須セクションの枠、英語）`[必須]`

**DoD**: `docker compose up --build` 一発で HTTPS のページが開き、サインアップ/ログインでき、Privacy/ToS がフッターから見られる。CI が回る。

- [ ] 駒ごとの合法手生成（移動・ツケ・新）
- [ ] 初期配置フェーズのルール実装
- [ ] 勝敗判定（帥の捕獲）・引き分け/投了処理
- [ ] エンジンの単体テスト網羅（ルール仕様書と1:1対応）

### 対局機能 (Web対戦ゲーム 2pt + リモートプレイヤー 2pt + WebSocket 2pt)
- [ ] WebSocket 基盤（接続管理・ルーム・ブロードキャスト）(2pt)
- [ ] 対局ルーム管理（作成・参加・状態遷移）
- [ ] サーバー権威の手検証フロー（client → server 検証 → 全員に配信）
- [ ] 盤面 UI（2D、駒の積み重ね表示、合法手ハイライト、レスポンシブ）`[必須: レスポンシブ]`
- [ ] 初期配置フェーズの UI
- [ ] 切断・再接続処理（一定時間の対局保持、復帰ロジック）(リモート 2pt の要件)
- [ ] 別マシン間でのライブ対戦の動作確認
- [ ] 同時対局・同時操作の負荷/競合テスト `[必須: マルチユーザー同時利用]`

**DoD**: 2人が別々のPCからログインし、軍儀を最初から最後まで対局でき、途中切断→再接続しても続行できる。
